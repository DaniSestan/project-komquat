# CHANGELOG Template

## Overview
Changelogs can be automatically generated with the use of software.

For those opting to manually create a changelog, or a template for generating changelogs, any progress to the 
software is defined between unreleased changes and versioned software. 

For more information on versioning software refer to https://semver.org/.

## Changelog categories

### Unreleased software

```
Any work aligning with major/minor/patch releases becomes part of an official release through one of two possible 
options to verify released changes:

- Tests (Manual or programmed unit tests)
  - Note: Larger applications developed in a staging environment are released to QA teams; 
    Small-scale projects, including those developed in staging environments, can either be passively monitored for 
    issues prior to release or published as an 'unstable' release for end-users who wish to test it in their own 
    sandbox environment.
- Monitoring (Passively monitoring code for any issues)
  - Note: Actively monitoring code for unstable changes is not recommended because it's 
    the equivalent of manual testing over an extended timeline.
```

### Major software version release

Features work: Software capabilities offering additional services

### Minor software version release

Refactoring work: Improving performance of existing services

### Patched software version release

Patch work: Resolving issues found in major/minor software releases

## Common attributes

Each category typically includes information about the following:

- Changes listed in chronological order
- Documentation
- Testing
